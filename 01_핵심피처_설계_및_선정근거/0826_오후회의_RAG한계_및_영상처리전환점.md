발표 듣고 느낀 점

내가 원하는 수준의 Rag 구축이 안되어있었다. 근거가 부족한데 할루시네이션도 있고 그런 것 설명을 들어보니 최후의 판단은 엔지니어가 하니깐 피룡없다. 울니 그런거 없이 사용자에게 주니깐 LLM, RAG, Agent가 전부 다 필요하다고 생각한 것에 변화가 생김
RAG는 문서자체 근거로 답변을 하지만 LLM은 최소 20%는 할루시네이션이 있다.
하네스 엔지니어링을 한다든가 등을 할 수 있긴 하다.

느꼈던 건데 영상을 업로드 하면 그것을 기다리는데 사용자들은 1조 보면 데이터 이동이 제일 많아 보이고 그런 곳과 비교하면 우리는 양반 수준, 데이터를 잘 저장하고 압축하고 JSON 형식 변환 등 잘 해놓으면 DB 문제는 없을 거라고 생각한다.

png는 용량을 많이 차니 그것을 삭제하는 방향으로 가자는 의견 jpg로 바꿔도 되고 모델 성능만 상관 없다면 이건 우선 나중에 이야기 하자
일단 웹사이트에서 생각보다 영상 돌아가는 시간이 오래 걸린다. BBOX 객체 탐지가 되어야 Halpe26이 돌아간다. 모델이 돌아갈 때 사용자는 할게 없으니 비동기로 하고 앱으로 한다면 그 사이 공백을 채워줄 것 생각 중, 완료가 되면 팝업을 띄울 방향도 하고
모델 성능을 뜰러오리리ㅜ 위해 이것저것 테스트해보고 최후의 수단으로 모델을 바꾼다.
LLM 버려도 되겠다 싶더라 LLM 업이 충분히 성능이 나오면 LLM 안써도 된다

pgvevtor, oracle, mysql 에 대해 알아보고 확실히 대비를 하는게 좋을 것 같다.

LLM에게 어느정도 디테일을 맡길지 생각해봈는데 정확도 높은 로직을 짜는게 맞고 그 부분에 관해서 더 고민ㅇ르 해봐야겠다. 속도적인 측면도 전다꼐에서 생각하는게 좋고 리포트 형식으로 만
들어면 LLM을 써야할 것 같기는 한데 할루시네이션 생각하다 보니깐 리포트를 작성하는 것은 좋긶나데 글머 LLM 은 확률기반이ㅣ깐 확률기반으로 피드백이 달라질 수 있다.
배우는것 대부분이 LLM이 여기저기 있으니 그것을 제한하는 것을 배운다고 생각함 요즘 트렌드가 하네스 엔지니어링이고 그것 관련 AI를 어떻게 할 것인가 그런게 트랜드라 그런걸 반영해서 리포트쪽을 구성하고 싶다. md 로 묶어서 agent 역할을 하는 구체적 형식(agent.md) 
그런식으로 구현 할 생각 LLM 이 필요 없다면 안 쓰는게 낫다.
통제를 많이 할 수록 모델 성능이 오르니깐 그런 부분 공유 하겠다.
