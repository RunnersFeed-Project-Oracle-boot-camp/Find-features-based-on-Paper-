
네. 지금 말씀하신 걸 보면 **연구 주제가 상당히 선명해지고 있습니다.**  
제가 보기에는 지금은 이렇게 정리하면 가장 좋습니다.

## 1. 연구 주제

> **러닝 자세 분석을 기반으로 올바른 러닝 자세와 개인의 평소 상태와 다른 움직임 변화를 알려주는 AI 에이전트 서비스**

목표는 크게 두 가지입니다.

### ① 러닝 자세 교정

논문에서 검증된

- 관절각
    
- 보폭
    
- 케이던스
    
- 지면 접촉 시간
    
- 몸통 기울기
    
- 좌우 비대칭
    
- 기타 biomechanical 지표
    

등을 활용해서 **현재 러닝 자세가 어떤 특성을 보이는지** 알려줍니다.

### ② 컨디션/움직임 변화 감지

여기서 중요한 표현은 **"질병을 진단한다"가 아니라 "평소와 다른 움직임 변화를 알려준다"**입니다.

예를 들어:

> 평소보다 오른쪽 무릎 움직임의 좌우 비대칭이 증가했습니다.

> 평소 러닝보다 cadence가 감소했습니다.

> 이전 러닝 대비 trunk inclination이 크게 변했습니다.

그리고 이러한 변화가 **문헌에서 피로·컨디션 저하·부상 위험 관련 지표로 보고된 적이 있는지**를 함께 알려주는 겁니다.

```text
   ↓

```

이렇게 됩니다.

# 3. 여기서 LLM의 역할도 명확해집니다

LLM에게 **"올바른 자세가 뭔지 알아서 판단해라"**라고 하는 게 아닙니다.

오히려:

> **논문에서 근거가 있는 지표를 찾아서 구조화하고, 그 지표를 데이터셋에서 계산하고, 결과를 사람이 이해하기 쉬운 언어로 설명한다.**

가 LLM의 역할입니다.

예를 들어 논문 분석 결과:

```text
Feature: Trunk inclination

Evidence:
여러 연구에서 달리기 조건에 따라 trunk inclination의 변화가 관찰됨.

Measurement:
hip - shoulder 등의 pose keypoint를 이용해 계산 가능.

Dataset:
RGB video에서 계산 가능.

```

그러면 실제 사용자가 달린 후:

```text
이번 러닝에서

Trunk inclination
평소 평균: 8.2°
이번 러닝: 13.7°

변화: +5.5°
```

같은 결과를 얻을 수 있습니다.

그리고 LLM이:

> "이번 러닝에서는 평소보다 상체가 더 앞으로 기울어진 것으로 나타났습니다. 관련 연구에서는 달리기 조건 및 피로 상태에 따라 몸통 움직임이 변화할 수 있다고 보고되어 있습니다."

처럼 **설명해주는 것**입니다.

단, **"따라서 피로입니다"라고 진단하면 안 됩니다.**

# 4. 여기서 "임베딩"은 두 가지로 분리하는 게 좋습니다

주환님이 말씀하신

> "논문에서의 관절각도 등을 임베딩해서 LLM 분석"

은 조금 수정하는 게 좋습니다.

### 논문 텍스트 → Embedding

이건 **논문 간 의미적 유사성**을 찾는 데 사용합니다.

```text
논문 A ─┐
논문 B ─┼→ Embedding → Similarity → Clustering
논문 C ─┘
```

반면

### 관절각도 → 숫자 Feature

이건 **실제 러닝 데이터를 분석하는 것**입니다.

```text
영상
 ↓
Pose
 ↓
관절 좌표
 ↓
Knee angle = 72°
Hip angle = ...
Trunk angle = ...
Cadence = ...
```

즉 **논문 임베딩과 러닝 데이터 feature는 별개의 것**으로 생각하는 게 좋습니다.

# 6. 그리고 "올바른 러닝 자세"라는 표현은 조금 조심해야 합니다

이건 연구할 때 굉장히 중요합니다.

**모든 사람에게 하나의 정답 자세가 존재한다고 가정하면 위험합니다.**

사람마다

- 신체 비율
    
- 달리기 속도
    
- 숙련도
    
- 체격
    
- 유연성
    
- 과거 부상
    
- 달리는 목적
    

등이 다르기 때문입니다.

그래서 연구 제목/서비스에서는

> **"올바른 러닝 자세 판정"**

보다는

> **"문헌 기반 러닝 자세 지표 분석 및 개인별 자세 피드백"**

이 더 연구적으로 안전합니다.

즉,

**절대적인 정답 자세를 판정하는 게 아니라**

> **문헌에서 보고된 지표 + 개인의 baseline + 현재 변화**

를 같이 보는 겁니다.

---

# 7. 그래서 최종적으로 이런 서비스가 됩니다

사용자가 스마트폰으로 달리는 영상을 찍습니다.

```text
📱 Running Video
       ↓
Pose Estimation
       ↓
┌─────────────────────────┐
│ Knee Angle              │
│ Hip Angle               │
│ Trunk Angle             │
│ Cadence                 │
│ Symmetry                │
│ Stride-related metrics  │
└────────────┬────────────┘
             ↓
       Personal Baseline
             ↓
        변화량 분석
             ↓
      Literature Evidence
             ↓
            LLM
             ↓
┌─────────────────────────────┐
│ 이번 러닝에서 평소보다       │
│ 상체 전방 기울기가 증가했습니다. │
│                             │
│ 해당 지표는 문헌에서         │
│ 피로/러닝 조건 변화와        │
│ 관련하여 연구된 바 있습니다. │
│                             │
│ ※ 의학적 진단은 아닙니다.    │
└─────────────────────────────┘
```

이렇게 되면 단순히 **"AI로 달리기 자세를 분석했다"**가 아니라,

> **문헌 → 지표 → 영상 데이터 → 개인 baseline → 변화 탐지 → 근거 기반 피드백**

이라는 하나의 연구 스토리가 만들어집니다.

## 지금 주환님이 적어놓으신 내용을 연구계획서 형태로 정리하면

### 주제

**문헌 기반 러닝 자세 분석 및 개인별 움직임 변화 탐지를 통한 AI 러닝 피드백 에이전트 개발**

### 연구 목적

러닝 관련 선행연구에서 제시된 biomechanical 지표를 분석하고, 러닝 이미지/영상 데이터에서 해당 지표를 추출하여 개인의 러닝 자세와 평소 상태와의 차이를 분석한다. 이를 바탕으로 사용자에게 근거 기반의 러닝 자세 피드백 및 움직임 변화 정보를 제공하는 AI 에이전트 서비스를 구축한다.

### 데이터

- 러닝 이미지 데이터
    
- 러닝 영상 데이터
    
- Pose/keypoint 데이터
    
- 러닝 biomechanics 데이터셋
    
- 선행연구 논문 및 PDF
    

### 연구 과정

**① 논문 수집**

→ 러닝 자세 / fatigue / condition / injury-related biomechanics / running intervention 연구 수집

**② 논문 분석**

→ LLM을 이용해 논문의 연구 대상, 실험방법, 관절각도 및 biomechanical feature, 주요 결과 추출

**③ 문헌 임베딩 및 유사도 분석**

→ 논문 간 semantic similarity 분석  
→ 연구 cluster 발견  
→ 반복적으로 등장하는 핵심 feature 탐색

**④ Feature 선정**

→ 문헌 근거  
→ 데이터셋에서 측정 가능 여부  
→ Pose Estimation 가능 여부  
→ 개인별 비교 가능 여부

를 기준으로 최종 feature 선정

**⑤ 영상 분석**

→ Pose Estimation  
→ 관절 좌표 추출  
→ 관절각/시간적 움직임 등 feature 계산

**⑥ 개인 baseline 구축**

→ 사용자의 평소 러닝 데이터를 기반으로 baseline 생성

**⑦ 변화 탐지**

→ 현재 러닝과 baseline 비교  
→ 평소와 다른 움직임 탐지

**⑧ LLM 피드백**

→ 측정 결과 + 문헌 evidence를 바탕으로 사용자에게 이해하기 쉬운 설명 제공

**⑨ 서비스화**

→ 러닝 영상 업로드  
→ 분석  
→ 시각화  
→ 피드백 제공

다음 단계에서는 **"이 연구에서 정말 핵심이 되는 질문이 무엇인가"** 하나만 잡으면 됩니다.

예를 들면:

이 정도가 현재 아이디어의 중심축으로 보입니다.

그 다음에야 **69편 논문 → feature → 데이터셋 → 실험 설계**를 연결하면 됩니다.
